Resource optimization, 2026-09-09

The original repository is `~/myworld/WorkspaceManager`. The separate
`~/cld/WorkspaceManager-efficiency` directory was inspected as prior work; its
incremental title-index and paging approach was adapted here. Existing window
restoration and appearance edits remain in the working tree.

Changes implemented:

- Replaced the two-second activity stat loop with FSEvents. Known changed files
  are statted; indicator expiration uses cached timestamps and a one-shot timer.
- Cached compact Claude, Codex, and Gemini parse results by inode, size and mtime.
  Removed files and entries outside the discovery window are evicted. Timestamp
  parsing uses reusable immutable format styles.
- Retained a 30-second reconciliation for event loss, new roots and recency
  expiration. Scans coalesce instead of accumulating behind a busy scan queue.
- Suspended display scanners while all application windows are occluded or
  minimized; resumed with reconciliation. Window consumers share the scanners,
  and closing one window does not stop another window's updates.
- Paged Quick history in groups of 30. Indexed titles incrementally, preserving
  tracking for open sessions outside the loaded page and releasing it on close.
- Streamed the installed CLI's string table instead of retaining the entire
  output, and cached discovered model metadata until the CLI changes. Replaced
  the environment-dependent Opus 5 assertion with an actual `strings` fixture
  test that also verifies invalidation on binary replacement.
- Avoided terminal fit bridge calls when its dimensions are unchanged, and
  removed the root view's redundant subscription to activity changes. Activity
  views still observe their own data. Colors, fonts and animation styling were
  not changed by this optimization.

Measured with Swift 6.4, macOS 27.0, arm64, using separate `swiftc -O` benchmark
executables. Baseline source is revision `e88f8d5`. The harness changes access
control in temporary baseline copies solely to call the original cached scan.
No user transcripts, CLI sessions or application windows are opened by it.

| Synthetic workload | Baseline | Optimized |
| --- | ---: | ---: |
| 100 activity files, first scan | 150.8 ms | 37.0 ms |
| Same files, 10 unchanged scans | 1,439.7 ms | 34.8 ms |
| Activity parses, initial plus 10 scans | 1,100 | 100 |
| Quick history first load | 888.8 ms | 164.4 ms |
| Quick first-load content reads | 85,157,470 bytes | 65,997,037 bytes |
| 10 small appends to a loaded Quick transcript | 224.8 ms | 13.5 ms |
| Content read for those 10 appends | 21,291,890 bytes | 460 bytes |

Quick fixtures contain 40 files of approximately 2 MB each. The baseline loads
all 40; the optimized first page reads 30 plus one lookahead. This deliberate
workload reduction is part of the first-load comparison. Append comparisons
operate on the same already-loaded file. Baseline content-byte counts follow its
full-file reads; optimized counts are recorded by the index. Timing is a local
sample, not a guarantee or a measurement of whole-app CPU, WindowServer or GPU
usage. The running installed application has not been replaced for this report.

Reproduce from the repository root:

```sh
./scripts/test-isolated.sh
swift build -c release
python3 scripts/benchmark-scanners.py e88f8d5
```

Benchmark JSON, binaries and `/usr/bin/time -l` output are written under
`.build/scanner-benchmark/`. Tests cover real filesystem notification delivery,
watcher stop/restart, cache invalidation and eviction, partial Unicode records,
title paging and tracking, visibility transitions and shared scanner consumers.

The title index assumes the CLIs' append-only JSONL format. It detects file
replacement, truncation and same-size edits; an in-place rewrite that grows a
file requires a full re-index if a CLI adopts that behavior. Individual records
over 256 KiB are skipped to bound tool-output buffering. Cold indexing still
reads a requested file once. Classic Gemini's JSON documents are parsed in full
when changed, because they are rewritten documents rather than append-only
JSONL; unchanged documents are not reread. A dropped filesystem event or a
previously absent root is recovered by the 30-second reconciliation.
